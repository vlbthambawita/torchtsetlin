# Decisions log — IMN × Tsetlin machine

Dated entries; each one is a deviation from, or clarification of, the paper (Kadra, Pineda
Arango & Grabocka, *Interpretable Mesomorphic Networks for Tabular Data*, NeurIPS 2024) or the
official code (https://github.com/ArlindKadra/IMN, read 2026-10-14), or a design choice for the
new TM arms. Record new decisions here, not silently in code.

## 2026-10-14 — set-up

| # | Item | Decision and reason |
|---|---|---|
| D1 | Library access | `src/torchtsetlin/**` is read-only (C1). The TM is used through its public API; two private helpers are *read* (`_signed_weights`, `_votes(clamp=False)`) to build the clause basis and to test it. `tests/test_imn.py::test_library_untouched` checks `git diff src/` is empty. |
| D2 | Splits | Every arm uses the same stratified 60/20/20 train/valid/test split per seed (the official code's `hpo_tuning=True` protocol). The paper's default-hyper-parameter numbers (Table 8) were trained on 80 % with no validation split, so our numbers are not directly comparable to Table 8; it is shown as a sanity reference only. The TM arms need a validation split for epoch selection, and giving it to all arms keeps the comparison fair. |
| D3 | Categorical encoding | Official code defaults: `TargetEncoder` for binary tasks, `OrdinalEncoder` for multi-class (the paper text says one-hot). Missing categories become their own category; numerical NaN → 0 after standardization. |
| D4 | Data access | `sklearn.datasets.fetch_openml(data_id=...)` with cache in `.cache/openml` (git-ignored) instead of the `openml` package (not installed). |
| D5 | Multi-class AUROC | Macro one-vs-rest. The official script passes `multi_class='raise'` for multi-class, which sklearn rejects, so its multi-class protocol is unknown. |
| D6 | Snapshot ensembling | Average snapshot *logits* (official: probabilities). The local model is linear in its generated parameters, so the ensemble is one local model per example and the explained model is the predicting model. |
| D7 | Epoch budget | Official default 500 epochs, batch 64. `max_steps` exists to cap very large datasets (Tier 2); any cap is preregistered in PLAN.md §6 before Tier 2 starts and applied to every neural arm alike. |
| D8 | GBDT baseline | CatBoost is not installed; `gbdt` uses CatBoost when importable, else `sklearn.HistGradientBoostingClassifier`. The record stores which one ran (`info.impl`). Installing `catboost`/`optuna` changes the user's environment and needs their OK. |
| D9 | TM initialisation of clause weights | `clause_init = tm_weight · tm_init_scale / T` (scale 1). With the generator's output layer zero-initialised, `imn_tm`, `imn_hybrid` and `clause_lr` start out *exactly* as the source TM's (unclamped) vote divided by `T`, for every input (tested). |
| D10 | XAI benchmark | Self-contained re-implementation of the three XAI-Bench families (`code/xai.py`) with exact ground-truth contributions, instead of the XAI-Bench package. Metric definitions are in that file and differ in detail from XAI-Bench (fixed baseline instead of conditional expectation). |
| D11 | HPO | Seeded random search with an equal trial budget for every arm (Optuna/TPE not installed). |
| D12 | Not replicated from the official code | Data augmentation (official default probability 0) and the minority-class oversampling block in `main_experiment.py` (dead code: `fit` is called on the original `X_train`). |
| D13 | Clause basis | From the trained TM: drop empty clauses, merge exact duplicates (summing their signed votes). Polarity and class ownership survive only through the initial weights; the generator may give any clause any sign on any output. |
| D14 | TM probabilities | `softmax(v / T)` on clamped vote sums (the library's `predict_proba_from_votes`); AUROC is rank-based, so this only matters for log-loss and for the multi-class one-vs-rest AUROC. |
| D15 | L1 penalty | Official form `weight_norm · mean(|w|)` over all generated parameters incl. the bias row (`l1_mode="all"`, the default for every arm). Two variants exist for the clause arms: `"active"` (only terms whose feature/clause is non-zero) and `"prior"` (`|w − w_prior|`, shrink toward the TM's votes instead of toward 0). Added after the pilot showed `imn_tm` over-fitting credit-g (train AUROC 1.00); which one becomes the `imn_tm` default is decided on *validation* AUROC in Phase 1 (PLAN.md §8) and recorded here. |

## 2026-10-14 — Phase 1

| # | Item | Decision and reason |
|---|---|---|
| D16 | Phase-1 datasets | The regulariser sweep uses phoneme 1489 and kc1 1067 instead of adult and jungle-chess. A 500-epoch neural run on those two takes about 11 min (pilot), and the sweep has 9 settings × 3 seeds × 2 arms, so including them would cost about 20 GPU-h for selection alone. The six datasets are phoneme, kc1, credit-g, vehicle, blood-transfusion and Australian (5 binary, 1 multi-class). |
| D17 | Selection rule | For each arm (`imn_tm`, `imn_hybrid`), pick the (`l1_mode`, `weight_norm`) with the highest mean **validation** AUROC. The mean is taken over datasets of the per-dataset seed means. Ties within 0.001 go to the official setting (`all`, 0.1). `imn_tm_rand` uses the `imn_tm` choice. `tm_gated` and `clause_lr` keep the official default: `tm_gated` has a zero prior, and `clause_lr` has no generator. Implemented in `code/select_reg.py`; the outcome is appended below. |
| D18 | Execution | Sweeps run through `code/jobs.py` (file queue, 3 workers per GPU). The source-TM cache takes a per-key file lock and writes atomically, so concurrent workers never train the same source TM twice. |
| D19 | Phase-1 outcome (2026-10-14) | 324/324 records, 0 failures (`results/reg/SELECTION.md`, `selection.json`). Both `imn_tm` and `imn_hybrid` choose **`l1_mode="prior"`, `weight_norm=1`**: shrink toward the TM's votes. The mean validation AUROC is 0.8508 for `imn_tm` (official `all_0.1`: 0.8461) and 0.8510 for `imn_hybrid` (0.8454). Caveats: (i) the spread across the 9 settings is only about 0.005 validation AUROC; (ii) the winner is at the **edge** of the grid (largest λ), so the optimum may be stronger. Phase 3 therefore widens the L1 range for the clause arms to [1e-5, 10]. `imn_tm_rand` uses the same setting. Its basis has no TM prior (zero init), so for it `prior` equals `all` with λ = 1. |

## 2026-10-14 — Phases 3–6 (preregistered before any of these runs)

| # | Item | Decision and reason |
|---|---|---|
| D20 | HPO budget | **20** random-search trials per (arm, dataset) on split seed 0, not the 30 in PLAN.md §6. With 30, the trials and finals would not finish in one working day on two GPUs. The budget is equal for all arms. The selection key is seed-0 validation AUROC. The winners are re-run on seeds 0–4 (stage `hpo_final`), and those records are the tuned results. Two-stage order: the `tm` arm is tuned first, and its per-dataset winner is the fixed source TM of every clause arm's trials (stage b). Sampler: `code/hpo.py::sample`, using a per-(arm, dataset) RNG seeded from the names. |
| D21 | Baseline search spaces | Spaces as in paper Tables 11–15. The clause arms search L1 over [1e-5, 10] (D19) and `l1_mode ∈ {all, active, prior}`; `tm_gated` searches only the weight. CatBoost is unavailable, so its space is mapped onto HistGradientBoosting: `learning_rate` [1e-5, 1] log, `max_iter` [100, 4000] (CatBoost `iterations`), and `l2_regularization` [1, 10] log (`l2_leaf_reg`). `random_strength`, `bagging_temperature` and `leaf_estimation_iterations` have no HGB counterpart. sklearn hyper-parameters travel in the record's `nn_overrides`. |
| D22 | Phase 4 (XAI) | 3 families × ρ ∈ {0, 0.25, 0.5, 0.75} × seeds 0–4, d = 8, n = 10,000. Arms: `lr gbdt tabresnet imn tm clause_lr imn_tm imn_hybrid tm_gated`, at main-stage defaults (clause arms with D19). Every example in the 500-row sub-sample is explained. Known bias: `infidelity` uses small Gaussian perturbations, which penalise piecewise-constant (clause) models whose output jumps. `gt_corr` is the headline metric. |
| D23 | Phase 5 (ablations) | Tier 1, seeds 0–2, compared with the main-stage records of the same seeds. Configurations: source TM with 50 / 800 clauses per class (`tm` and `imn_tm`, tags `tm50` / `tm800`); no TM initialisation (`imn_tm`, tag `noinit`); generator input `[x, c(x)]` (`imn_tm_xc`); random clauses matched on firing rate (`imn_tm_randfr`); and `imn_hybrid` with a separate linear-block L1 of 0.1 (tag `split`; this tests the hypothesis in the main-stage summary that the strong prior penalty suppresses the linear term). The regulariser ablation itself is Phase 1. |
| D24 | Phase 6 (Tier 2) | The 23 remaining datasets × 12 arms × seeds 0–2, at main-stage defaults with three preregistered changes. (i) All neural arms are capped at `max_steps = 50,000` (D7); without it airlines and albert need about 2.5 M steps per run. (ii) The source TM runs at most 20 epochs with patience 5. (iii) helena (100 classes) uses 20 clauses per class, because the default 200 gives a 20k-clause basis and a 2.6 × 10^8-parameter `imn_tm` head. Any model above 4 × 10^7 parameters is **recorded as skipped** (`status: skipped`, with the reason), not silently dropped. Failures are reported per dataset. |
| D25 | Tier-2 data availability (2026-10-14) | guillermo 41159 and robert 41165 fail OpenML's MD5 check on three fresh downloads: the served file no longer matches the dataset description. albert 41147 returns HTTP 500. Unverified files are not used, so Tier 2 runs on the **20** remaining datasets. |
| D26 | Run-time fixes (2026-10-14) | (i) Two `hpo` trials of `imn_hybrid` on segment (800 clauses per class × 7 classes) ran out of GPU memory in the removal-attribution loop. `arms.run_neural.local` now evaluates the local model in row sub-batches of about 64 MB. Training and predictions are unchanged, and the two trials were re-run. (ii) The 720 `hpo_final` jobs (144 winners × seeds 0–4) were prepended to `jobs/xai.jsonl` so the running workers take them before Phase 4/6. Their records still go to `results/hpo_final/`. |
| D27 | Inference memory (2026-10-15) | Seven Tier-2 runs of the clause arms (helena with 20 clauses × 100 classes, and Fashion-MNIST) ran out of GPU memory in `ensemble_forward`, which generated a 4096 × P × K weight tensor per chunk. The chunk now shrinks so the tensor holds at most 64M elements. The change applies only when P·K > 15,625, and every existing record was produced before it, so none of them changes. Re-running a wide HPO trial, e.g. 800 clauses per class on segment, now takes smaller chunks: the logits are the same up to float summation order. Failed jobs are re-run with the patched code once the running workers drain the queue; running workers are not interrupted. |
| D28 | Wide-input memory (2026-10-15) | 46 Tier-2 jobs on wide datasets (riccardo, dilbert, christine, mfeat-factors, cnae-9, helena, Fashion-MNIST) ran out of GPU memory. Most failures were in removal attribution or clause evaluation; the rest are covered by D27. Three steps now take bounded row chunks: `ClauseBasis.evaluate` (literal matrix ≤ 30M elements), the TM's inference and `full` (same bound), and the masked copies in `removal_attributions` (≤ 20M floats). Clause evaluation is row-wise, so outputs are exact. For every Tier-1 dataset the bounds do not bind, so all chunk sizes stay as before. The 46 jobs were re-run with 2 workers per GPU. |
