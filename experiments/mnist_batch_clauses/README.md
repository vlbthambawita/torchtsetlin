# mnist_batch_clauses: batch size × clauses per class on MNIST, flat vs convolutional TM

**Question.** How does the final accuracy of torchtsetlin's batched feedback depend on the
mini-batch size (1 … 1024), and does that change with model size (1 000 … 64 000 clauses per
class) and between a flat and a convolutional TM? For the JMLR paper's *Batched versus sequential
feedback* section. Plan (decisions D0–D10, hypotheses, cost): `plans/mnist-batch-clauses.md`.

`REPORT.md` / `REPORT_smoke.md` are generated by `code/report.py` from `results/`; do not hand-edit.

## Rules

| # | Rule |
|---|---|
| R1 | `src/torchtsetlin/**` is **read-only** here. Library defects go to `LIBRARY_GAPS.md`. |
| R2 | Every number comes from a `results/<arm>/*.json` record carrying `argv`, `seed`, `git_sha`, `env` (incl. the torchtsetlin version and GPU). Nothing is hand-typed. W&B is a mirror, not the record. |
| R3 | No tuning: hyper-parameters are the paper's B4 (flat) and B7 (conv); only C, B and T (D2) vary. |
| R4 | Early stopping watches the **validation** split, never the test set (D3a). Test accuracy is logged every epoch but never used for a decision. |
| R5 | GPU runs beyond the smoke test need the user's go-ahead; seed-0 grid cells run on the RTX 3090 alone (timings, D8). |

## Protocol (summary of the plan)

- **Data:** the paper's MNIST Booleanizations, byte for byte (`experiments/paper_experiments/.cache/data/B4.npz`, `B7.npz`, sha256
  checked against that programme's manifest). 60 000 training images split once into **50 000 train /
  10 000 validation**, stratified, seed 0 (`results/split.json`, index hash re-checked on every load);
  the official 10 000 test images.
- **Models:** flat = `TsetlinMachine(784, 10, C, T, s=10, weighted=False)`; conv =
  `ConvTsetlinMachine(10, C, T, s=5, patch_size=10, position_encoding=True, weighted=True)`;
  boosted true-positive feedback. **C is per class** (D0). **T = T_ref · C / 2000** (flat T_ref = 50,
  conv 5 000) in the grid; T fixed at T_ref in the `control_T` arm (D2).
- **Training:** `feedback_mode="batch"` with batch B (`control_seq`: `"sequential"`, D6). The data order
  depends only on the seed (identical across B and C, D7).
- **Early stopping (D3):** stop after **25 epochs** without a validation improvement of **≥ 0.05 pp**
  (counted in examples, 5 of 10 000), not before epoch 30, at most 500 epochs or 24 h of
  train + eval time. The stopping state (best value, best epoch, counter) is part of the checkpoint,
  so an interrupted and resumed run stops exactly where an uninterrupted one would
  (`results/smoke/resume_check.json`: bit-identical curves on CPU and CUDA).
- **Statistic (D4):** test accuracy at the best-validation epoch, read from the per-epoch curve (the
  test set is evaluated every epoch, so no best-model checkpoint is needed); mean ± sd over seeds 0–2.
  Also recorded: best epoch, commits and GPU-seconds to best, epoch-30 test accuracy, stop reason.

## Layout

| Path | What |
|---|---|
| `code/common.py` | paths, grid (`CLAUSES`, `BATCHES`, `jobs(arm)`), B4/B7 configs, T rule, data + split, records |
| `code/train.py` | one run (or `--calibrate N` for Phase 0 pricing) |
| `code/tracking.py` | W&B mirror, `simulamet_mlc/torchtsetlin`, group `mnist_batch_clauses`, run id `mbc-<tag>` |
| `code/queue_runner.py` | one GPU's worker over an arm; claims in `.cache/claims/`; seed-0 grid only on a 3090 |
| `code/report.py` | `REPORT.md`, `results/summary.json`, `figures/`; `--paper` writes the paper's `generated/batch_clauses_*.tex` + figures |
| `code/smoke.sh` | the smoke test |
| `results/<arm>/<tag>.json` | one record per run; tag = `<model>_c<C>_b<B>_T<scaled|fixed>[_seq]_s<seed>` |
| `logs/`, `.cache/` | git-ignored: run logs, checkpoints, W&B files |

## Running

```bash
bash code/smoke.sh                                     # smoke test (done, see REPORT_smoke.md)
# Phase 0 pricing (needs go-ahead), e.g.:
python code/train.py --model conv --clauses 64000 --batch-size 1 --device cuda:0 --arm phase0 --calibrate 2000
# Phase 3 (needs go-ahead):
nohup python code/queue_runner.py --arm grid --seeds 0 --device cuda:0 > logs/q_grid_s0.log 2>&1 &
nohup python code/queue_runner.py --arm control_seq --device cuda:1 > logs/q_seq.log 2>&1 &
python code/report.py [--paper]
```
