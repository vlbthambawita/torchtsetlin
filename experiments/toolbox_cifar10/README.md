# toolbox_cifar10: torchtsetlin at the Optimized Toolbox's best CIFAR-10 setting

**Question.** With the best configuration that *An Optimized Toolbox for Advanced Image Processing
with Tsetlin Machine Composites* (Grønningsæter, Smørvik, Granmo 2024, arXiv:2406.00704) reports,
taken as is, what accuracy does the newest torchtsetlin reach, and how does it compare with the
published values? Only torchtsetlin is run; the paper's numbers are cited from its Table IV, the
authors' code (tmu) is not run. Plan: `plans/toolbox-cifar10.md`.

`REPORT.md` holds the results; it is generated by `code/report.py` from `results/*.json`. Do not
hand-edit it.

## Rules

| # | Rule |
|---|---|
| R1 | `src/torchtsetlin/**` is **read-only** here. Library defects go to `LIBRARY_GAPS.md`. |
| R2 | Every number comes from a `results/*.json` record carrying `argv`, `seed`, `git_sha`, `env` (incl. the torchtsetlin version). Nothing is hand-typed. |
| R3 | No tuning. Hyper-parameters are the paper's (Table III); departures are listed below. |
| R4 | The paper's protocol: no validation split, no epoch selection; the statistic is the mean ± sample variance of test accuracy over epochs 226–250 of 250. |

## Settings (fixed before any result)

| # | Item | Decision |
|---|---|---|
| M1 | Model | `ConvTsetlinMachine(10, 64000 per class, T, s, patch_size=window, stride=1, position_encoding=True, weighted=True, max_included_literals=32, budget_mode="soft")`; HOG is a flat `TsetlinMachine`, unweighted. 128 states per action and boosted true-positive feedback (both tmu's defaults and torchtsetlin's). tmu appends thermometer-coded patch coordinates; `position_encoding=True` does the same. |
| M2 | Table III vs the scripts | The scripts' defaults differ from Table III for adaptive Gaussian (10×10, T=1500, s=10 vs 5×5, T=2500, s=3.5) and the 5×5 augmented colour-thermometer script uses `patch_size=4`. **Table III is used** (`code/specialists.py`). |
| M3 | T at 64 000 clauses | §IV says "scale T thereafter", §IV-B and the scripts keep the 2 000-clause T. **T fixed**, as the code does. |
| M4 | Encoders | `code/encoders.py`, ported from the scripts. `code/check_encoders.py` compares all seven and the flip augmentation **bit for bit** with the authors' own code on 1 000 images: all identical (`results/encoder_check.json`). |
| M5 | Data | Official CIFAR-10 (50 000 / 10 000), loaded as `keras.datasets.cifar10.load_data()` returns it. Augmented specialists: every training image followed by its horizontal flip (100 000), as the scripts do. |
| M6 | Training | 250 epochs, a fresh random order every epoch, batched feedback with batch 50, one run (seed 0) per specialist, as the paper reports one run. Test class sums saved every epoch (`.cache/class_sums/`). |
| M7 | Composite | Eqs. 4–5: per epoch, each specialist's test class sums divided by their `max − min`, summed, argmax; mean ± sample variance over epochs 226–250. Transductive over the test set, as published. Teams: all 22 (the paper's 82.8) and the 11 non-augmented ones (not published). |
| M8 | Verdict | **REPRODUCED** if within **1.5 pp** of the paper's value, otherwise **GAP**. |

## Deviations

| # | Deviation | Why |
|---|---|---|
| D1 | Batched feedback (batch 50) instead of tmu's per-example updates | The library's default mode; an update per example at 640 000 clauses would take weeks per specialist. |
| D2 | HOG specialists at **16 000** clauses/class, compared with the paper's 16 000 cell (67.3 / 67.9; 64k: 67.5 / 68.5), and included at 16 000 in the composites | HOG has 11 664 literals per clause; 64 000 (27.8 GiB request) and 32 000 clauses/class run out of memory on the 24 GB RTX 3090 (`results/calibration/`). |

## Cost (measured, `results/calibration/`, 20 batches at the start of training)

| Specialist type, 64 000/class | GPU | s/epoch (train + test) | 250 epochs |
|---|---|---|---|
| 5×5 thermometers (2F = 1 308) | RTX 3090 | 438 + 55 | 34 h |
| 4×4 thermometers | RTX 3090 | 366 + 42 | 28 h |
| 3×3 thermometers | RTX 3080 | 325 + 31 | 25 h |
| 10×10 Canny / mean / Otsu (3 planes) | RTX 3080 | 227 + 28 | 18 h |
| 5×5 adaptive Gaussian (3 planes) | RTX 3080 | 182 + 13 | 14 h |
| HOG, 16 000/class | RTX 3090 | 51 + 1 | 4 h |

Augmented specialists train on twice the data. Total ≈ 700 GPU-h, about two weeks on the two GPUs.

## Running

```bash
python code/check_encoders.py                       # encoders vs the authors' code, bit for bit
python code/train.py --spec therm5 --calibrate 20   # cost of one specialist at 64k (no record)
nohup python code/queue_runner.py --device cuda:0 > logs/queue_gpu0.log 2>&1 &   # RTX 3090 queue
nohup python code/queue_runner.py --device cuda:1 > logs/queue_gpu1.log 2>&1 &   # RTX 3080 queue
python code/report.py                               # REPORT.md + paper/generated/toolbox_*.tex
```

An interrupted specialist resumes from its last checkpoint (every 5 epochs) when its queue is
restarted after removing its claim in `.cache/claims/`.
