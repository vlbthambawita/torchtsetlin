# multi_convtm — reproducing TM Composites on CIFAR-10

**Goal.** Reproduce the methods and the CIFAR-10 results of *TMComposites: Plug-and-Play
Collaboration Between Specialized Tsetlin Machines* (Granmo, 2023, arXiv:2309.04801) with
`torchtsetlin`. **No new methods.** Several convolutional/flat TMs with different
Booleanizations and convolution windows are trained independently, and their class sums are
normalised and added (Eqs. 7–8).

`REPORT.md` holds the results; it is generated by `code/report.py` from `results/*.json`. Do not
hand-edit it.

## Rules

| # | Rule |
|---|---|
| R1 | `src/torchtsetlin/**` is **read-only** in this programme. Library defects go to `LIBRARY_GAPS.md`, never fixed here. |
| R2 | Every reported number comes from a `results/*.json` record carrying `argv`, `seed`, `git_sha` and `env`. Nothing is hand-typed. |
| R3 | No new methods, no tuning. Hyperparameters are the paper's; any departure is listed under *Deviations*. |
| R4 | The paper's protocol is followed: no validation split, no epoch selection. Test accuracy is read at the fixed epoch the paper reports (100), never at the best epoch. |

## The specialists (Table 1, CIFAR-10 column; authors' scripts @ `91524f0`)

| id | Booleanization | Model | Clauses/class | T | s | Weighted |
|---|---|---|---|---|---|---|
| `T10` | `cv2.adaptiveThreshold(ch, 1, GAUSSIAN_C, BINARY, 11, 2)` per channel → 3 planes | conv 10×10 | 2 000 | 500 | 10.0 | yes |
| `C3` | 8-level colour thermometer, `x ≥ (z+1)·255/9` per channel → 24 planes | conv 3×3 | 2 000 | 1 500 | 2.5 | yes |
| `C4` | same as `C3` | conv 4×4 | 2 000 | 1 500 | 2.5 | yes |
| `HoG` | `cv2.HOGDescriptor((32,32),(12,12),(4,4),(4,4),18,1,-1,0,0.2,True,64,True)`, `≥ 0.1` → 5 832 bits | flat | 2 000 | 50 | 10.0 | no |

All specialists use a clause budget of 32 literals (`max_included_literals=32`, Table 1 caption).
"2K clauses" means **per class**: the scripts pass `number_of_clauses=2000` to tmu's `TMClassifier`, which builds one clause bank of that size per class.
Conv models append thermometer-encoded patch coordinates, as tmu does. Training uses the full 50,000 images for 100 epochs.

## Protocol

- Data: official CIFAR-10 (`data/cifar-10-batches-py`, tarball md5 `c58f3010…49a` verified),
  loaded exactly as `keras.datasets.cifar10.load_data()` returns it. The authors' class sums are
  in `data/tmcomposites_reference/`.
- Each specialist saves its **unclamped** test-set class sums after every epoch
  (`.cache/class_sums/<spec>_seed<k>/eNNN.npy`, git-ignored).
- Composite: `α_t = max − min` of specialist *t*'s class sums over the 10,000 test images, then
  `argmax_i Σ_t c_t^i / α_t`. This is exactly as `CIFAR10Team.py` computes it: transductive, as published.
- Seeds 0, 1, 2. The paper reports a single run.

## Pass criterion (fixed before any result)

A Table 2 row is **REPRODUCED** if the 3-seed mean at epoch 100 is within
`max(3.0 pp, 2 × seed sd)` of the paper's value; otherwise it is a **GAP**, with a documented
cause. The paper's two qualitative claims are checked separately:
- **C-A:** the four-specialist composite beats the best single specialist by about 12 points on CIFAR-10.
- **C-B:** each added specialist in Table 2's composite rows raises accuracy.

## Deviations from the paper (known before running)

| # | Deviation | Why it cannot be avoided here |
|---|---|---|
| D1 | `torchtsetlin` batched feedback, batch 50, instead of tmu's per-example updates | R1 + the user's choice of library. Batch 10–50 matches sequential on Noisy XOR (`docs/benchmarks.md`). At this exact budget, the `convtm` programme got 65.1% against the Toolbox's 64.5% for its 5×5 thermometer specialist. |
| D2 | Integer clause weights are floored at 0, while tmu floors them at 1 (`experiments/convtm/LIBRARY_GAPS.md` LG-006) | R1. The share of zero-weight clauses is measured from the final checkpoints. |
| D3 | Class sums are read through the model's internal `_evaluate`/`_votes(clamp=False)`, because `forward()` clamps to [−T, T] and tmu does not (`LIBRARY_GAPS.md` MC-1) | R1. The trainer asserts every epoch that clamping its sums reproduces `forward()` exactly. The clamped-vote accuracy is logged alongside. |
| D4 | Headline at epoch 100 (paper text: "after 100 epochs"). The authors' released files are epoch 99 (`_99_` = `epoch+1`). | Both are recorded. |

## Running: one line

```bash
./reproduce.sh                      # everything: data, tmu environment, torchtsetlin (hard and soft
                                    #   budget, 3 seeds), tmu (authors' scripts), REPORT.md, PROPOSAL.md
./reproduce.sh --quick              # 1-epoch smoke test of the whole pipeline, into .cache/quick/
./reproduce.sh --stages reference   # Table 2 from the authors' released class sums (seconds)
./reproduce.sh --stages report      # rebuild REPORT.md and PROPOSAL.md from results/
./reproduce.sh --stages torchtsetlin --variants soft --seeds 0 --gpus 1
```

`reproduce.sh` wraps `code/reproduce.py`:
- It schedules jobs on every visible GPU. HoG only runs on cards with about 20 GiB or more.
- It skips runs whose record says `done`, so re-running the same command resumes.
- The full run takes about 2 days on an RTX 3090 + RTX 3080; tmu, at 6-15 min per epoch, is the long pole.
