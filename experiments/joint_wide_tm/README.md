# joint_wide_tm: does joint feedback beat a TM Composite? (Fashion-MNIST)

**Question.** A *wide* TM runs several convolutional TMs side by side, each with its own filter
size, and adds their class scores. As a TM Composite (Granmo 2023, arXiv:2309.04801) the members
are trained independently. Here they are trained **jointly**: every member's Type I / Type II
feedback probability comes from the team's vote sum. At the same members, clauses, epochs and
data, is the joint team better, and is the gain more than "more clauses" or "a different T"?

Plan, review of the idea, hypotheses and the decision rule (fixed before any run):
`torchtsetlin_plans/experiments/joint_wide_tm/PLAN_FMNIST.md`.

`REPORT_*.md` are generated by `code/report.py` from `results/`; do not hand-edit.

## Design

Members: `ConvTsetlinMachine`, 2 000 clauses/class, weighted, soft literal budget 32, position bits.

| Member | Encoding | Patch | T | s |
|---|---|---|---|---|
| A10 | adaptive Gaussian threshold, 1 plane | 10×10 | 500 | 10.0 |
| H3 / H4 / H5 / H10 | thermometer, 8 planes | 3×3 / 4×4 / 5×5 / 10×10 | 1 500 | 2.5 |

Teams: **S** = H3 + H5 + H10 (filter sizes only), **P** = A10 + H3 + H4 (the paper's team).

| Arm | What |
|---|---|
| I | each member alone; `composite.py` combines them (scale from validation = primary; `v/T`; the paper's test-set scale) |
| E | seed ensemble of one member type (from I, no training) |
| J | joint team, rule `sum` (score Σv, threshold ΣT) or `one` (score T_i·Σ v_j/T_j, threshold T_i) |
| Jown | J with each member drawing its own negative class (ablation) |
| W | one member with the team's 6 000 clauses/class and T×3 (`sum`) or T×1 (`one`) |

## Layout

| Path | What |
|---|---|
| `code/common.py` | members, teams, paths, data (from fmnist_bitplanes) |
| `code/joint.py` | `JointConv` (two overrides + buffers), `JointTeam`, `learning_votes` (pass A) |
| `code/check_joint.py` | phase-0 checks T0–T6, T8 |
| `code/train.py` | one run of any arm, or `--calibrate N` (pricing, T7) |
| `code/composite.py` | composites and seed ensembles from the saved class sums; composite-best team file |
| `code/infer.py` | reload a saved team file; must reproduce its recorded test accuracy |
| `code/activation_maps.py` | per-member and team evidence maps of a saved team; map correlation |
| `code/queue_runner.py` | works through a phase on the 3080 |
| `code/report.py` | `REPORT_<phase>.md`; `--phase pilot --choose` writes the pilot choice |
| `code/smoke.sh` | phase 0 end to end |
| `results/<phase>/<arm>/<tag>.json` | one record per run |
| `models/<phase>/<arm>/<tag>.pt` | best-validation team files (git-ignored) |
| `.cache/sums/…` | per-epoch class sums of every member on validation and test (git-ignored) |

## Running

```bash
nohup bash code/smoke.sh > logs/smoke_driver.txt 2>&1 &                        # phase 0
nohup python code/queue_runner.py --phase pilot > logs/q_pilot.log 2>&1 &      # needs go-ahead
python code/composite.py --phase pilot --seeds 0 && python code/report.py --phase pilot --choose
nohup python code/queue_runner.py --phase main --seeds 0 1 2 > logs/q_main.log 2>&1 &   # needs go-ahead
python code/composite.py --phase main && python code/report.py --phase main
nohup python code/queue_runner.py --phase main --seeds 0 1 2 --jown > logs/q_jown.log 2>&1 &   # only if J wins
python code/infer.py models/main/J/S_sum_seed0.pt && python code/activation_maps.py models/main/J/S_sum_seed0.pt
python code/activation_maps.py models/main/Icomp/S_seed0.pt --indices-from results/main/activation/J/S_sum_seed0.json
```
